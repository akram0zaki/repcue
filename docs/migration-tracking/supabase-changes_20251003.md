## Database Changes

### Migration: 20251003-01-add-ai-workout-metadata.sql

**Type:** Schema Modification
**Table:** `workouts`
**Environment:** Development → Production

**Changes:**
1. Added column `ai_generated` (BOOLEAN, default: false)
   - Indicates whether a workout was generated by the AI Assistant
   - Nullable for backward compatibility

2. Added column `generated_at` (TIMESTAMPTZ, nullable)
   - Timestamp when the workout was generated by AI
   - ISO 8601 format

3. Added column `generation_params` (JSONB, nullable)
   - Stores generation parameters for future reference/regeneration
   - Structure: `{ goal, fitnessLevel, trainingStyle, timeAvailability }`

4. Created index `idx_workouts_ai_generated`
   - Partial index on `ai_generated` column (WHERE ai_generated = true)
   - Improves query performance for filtering AI-generated workouts

5. Created index `idx_workouts_generated_at`
   - Partial index on `generated_at` column (WHERE generated_at IS NOT NULL)
   - Improves query performance for sorting/filtering by generation date

**Rollback Plan:**
```sql
DROP INDEX IF EXISTS idx_workouts_generated_at;
DROP INDEX IF EXISTS idx_workouts_ai_generated;
ALTER TABLE workouts DROP COLUMN IF EXISTS generation_params;
ALTER TABLE workouts DROP COLUMN IF EXISTS generated_at;
ALTER TABLE workouts DROP COLUMN IF EXISTS ai_generated;
```

**Testing:**
- [ ] Migration runs successfully on development database
- [ ] Existing workouts remain unchanged (ai_generated = false by default)
- [ ] New workouts can be created with AI metadata
- [ ] Indexes improve query performance
- [ ] No breaking changes to existing queries

**Type:** New Function

**Files Created:**

2. `supabase/functions/generate-ai-workout/logger.ts` (65 lines)
   - Structured logging utility

   - Log levels: INFO, WARN, ERROR, DEBUG

3. `supabase/functions/generate-ai-workout/security.ts` (230 lines)
   - Input sanitization (XSS protection)
   - Rate limiting (5 requests/hour per user)
   - Request schema validation
   - Validates all user inputs (gender, age, height, weight, goal, etc.)

4. `supabase/functions/generate-ai-workout/ai-client.ts` (342 lines)
   - Model-agnostic AI provider interface
   - AnthropicProvider implementation (Claude 3.5 Sonnet)
   - OpenAIProvider implementation (GPT-4 Turbo)
   - Factory pattern for provider selection
   - Retry logic with exponential backoff
   - Automatic fallback to secondary provider
   - Timeout handling (60s)

5. `supabase/functions/generate-ai-workout/exercise-catalog.ts` (150 lines)
   - Fetches built-in exercises from database
   - Filters exercises by fitness level, training style, injuries
   - Groups exercises by category
   - Handles empty catalog gracefully

6. `supabase/functions/generate-ai-workout/prompt-builder.ts` (205 lines)
   - Constructs AI prompts from user profile
   - Professional coach system prompt
   - Explicit injury filtering instructions
   - Complete exercise catalog with ALL attributes
   - JSON schema enforcement
   - Safety-first design

7. `supabase/functions/generate-ai-workout/workout-generator.ts` (342 lines)
   - Main orchestration module
   - Coordinates: catalog → filter → prompt → AI → parse → validate
   - Parses AI response (JSON/markdown)
   - Validates workout structure
   - Generates UUIDs and metadata
   - Comprehensive error handling

**Environment Variables Required:**
- `SUPABASE_URL` - Supabase project URL
- `SUPABASE_ANON_KEY` - Supabase anonymous key
- `SUPABASE_SERVICE_ROLE_KEY` - Service role key for database access
- `AI_PROVIDER` - AI provider name ('anthropic' | 'openai', default: 'anthropic')
- `ANTHROPIC_API_KEY` - Anthropic API key (required if using Anthropic)
- `OPENAI_API_KEY` - OpenAI API key (optional, for fallback)
- `DEBUG` - Enable debug logging (optional, default: 'false')

**API Endpoint:**
```
POST /functions/v1/generate-ai-workout
Authorization: Bearer <JWT>
Content-Type: application/json

Request Body: AIWorkoutRequest
Response: { workouts: GeneratedWorkout[], metadata: { ... } }
```

**Security Features:**
