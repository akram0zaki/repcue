- **Mobile-first PWA** with WCAG 2.1 AA compliance and reduced motion respect
- **Use semantic, tokenized classes** instead of ad-hoc Tailwind colors
- **Typography, buttons, surfaces, status colors, RTL protections, and accessibility utilities** are centralized in `tokens.css`
- **Inline styles are not allowed**, except for passing CSS variables (e.g., `--progress`) when unavoidable

### Core Principles

- **Zero horizontal overflow** on mobile (min 320px width)
- **Touch targets ≥ 44×44px** for all interactive elements
- **Semantic typography scale** (`.text-h1` … `.text-small`)
- **Semantic color tokens** (text/surface/border/status) that adapt to light/dark modes

## ⚠️ CRITICAL CLARIFICATION: CSS Architecture Layers

RepCue uses **three distinct CSS layers** that must be understood separately:

### Layer 1: Tailwind Utilities (Auto-Generated, NOT in CSS files)
Classes like `space-y-3`, `flex`, `gap-2`, `px-4`, `py-2`, `rounded-lg`, `min-h-screen`, `flex-col`, `items-center`, `justify-center` etc. are **generated by Tailwind CSS at build time**. These classes **do not exist in any CSS file** - they're created dynamically by Tailwind's engine.

**How to modify Tailwind utilities:**
- Edit `tailwind.config.js` - Configure available utilities, colors, spacing scale, etc.
- Use `@tailwind` directives in `src/index.css` - Import Tailwind layers (base, components, utilities)
- Tailwind scans your component files (`.tsx`, `.ts`, `.jsx`) to generate only used classes

**Examples in RepCue**:
- Layout: `min-h-screen`, `flex`, `flex-col`, `grid`, `gap-4`, `p-4`, `mx-auto`, `max-w-md`
- Spacing: `py-2`, `px-4`, `mb-6`, `space-y-3`, `gap-2`
- Sizing: `w-16`, `h-16`, `w-full`
- Styling: `rounded-lg`, `border`, `shadow-md`, `bg-white`, `text-gray-800`
- Responsive: `md:text-xl`, `lg:flex`, `hidden sm:block`
- States: `hover:bg-blue-600`, `focus:outline-none`, `dark:bg-gray-800`

### How They Work Together

Example from actual code:
```css
/* Custom .btn-primary class uses CSS variables + Tailwind utilities */
.btn-primary {
  background-color: var(--color-primary);      /* CSS variable */
  color: var(--color-text-inverse);            /* CSS variable */
  border-radius: 8px;
  padding: 0.5rem 1rem;
  font-weight: 500;
  transition: all 0.2s ease-in-out;
  cursor: pointer;
  display: inline-flex;                         /* Could also use @apply px-4 py-2; */
  align-items: center;
  justify-content: center;
}

.btn-primary:hover {
  background-color: var(--color-primary-hover); /* CSS variable in dark mode context */
}
```

In JSX components:
```jsx
<button className="btn-primary px-4 py-2 rounded-lg gap-2 flex items-center">
  {/* 
    - .btn-primary: Custom CSS class (defines color, padding, display)
    - px-4 py-2: Tailwind utilities (16px horizontal padding, 8px vertical)
    - rounded-lg: Tailwind utility (border radius)
    - gap-2: Tailwind utility (8px gap between flex children)
    - flex items-center: Tailwind utilities (flexbox layout)
  */}
  Icon Text
</button>
```

## Styling Architecture Overview

RepCue combines three complementary systems:

1. **Tailwind CSS** (`@tailwind` directives in `src/index.css`)
   - Utility-first framework for responsive, maintainable layouts
   - Auto-generated classes based on configuration and usage
   - Modify via `tailwind.config.js` and component templates

2. **Design Tokens** (`src/styles/tokens.css`)
   - Semantic color system with automatic light/dark mode switching
   - CSS variables for theme consistency
   - iOS native app system colors for iOS PWA
   - Dynamic theme customization support

3. **Custom Components** (`src/index.css` @layer directives)
   - Reusable component-specific classes
   - Integration of Tailwind utilities via `@apply` directive
   - Custom CSS for specific interactions and animations
   - Accessibility-first design patterns


### Color System
**Background Colors**:
- Light: `.bg-surface-0`, `.bg-surface-50`, `.bg-surface-100`, ...
- Dark mode: Automatically inverts via `.dark .bg-surface-*` selector

**Text Colors**:
- Primary: `text-primary` or use CSS variable `var(--color-text-primary)`
- Secondary: `.text-secondary` or `var(--color-text-secondary)`
- Status: `.text-success`, `.text-warning`, `.text-error`

**Border Colors**:
- Default: `.border-surface-200 dark:.border-surface-700`
- Focus: `.border-primary` - Uses `var(--color-border-focus)`

### Spacing (Tailwind Utilities)
- Padding: `p-2`, `px-4`, `py-2` - Tailwind 8px grid
- Margin: `m-2`, `mx-auto`, `mb-4` - Tailwind 8px grid
- Gap: `gap-2`, `gap-4` - Tailwind flex/grid gaps
- Space-between: `space-y-3`, `space-x-2` - Tailwind child spacing

**Note**: These are all Tailwind utilities, NOT custom CSS.

### Typography
All typography uses custom classes with automatic dark mode support:
- Headings: `.text-h1` (32px), `.text-h2` (24px), `.text-h3` (20px)
- Body: `.text-body` (16px), `.text-small` (14px)
- Caption: `.text-caption` (12px)

All automatically apply:
- Correct font-size
- Correct font-weight
- Correct color from CSS variables
- Correct line-height

### Responsive Design (Tailwind)
All responsive behavior uses Tailwind breakpoint prefixes:
- `sm:` - 640px+
- `md:` - 768px+
- `lg:` - 1024px+
- `xl:` - 1280px+

Example:
```jsx

  {/* Mobile: flex-col (vertical), Desktop (768px+): flex-row (horizontal) */}

```

### Accessibility
- Keyboard focus: `:focus` states on buttons/inputs (custom CSS in tokens.css)
- Reduced motion: `@media (prefers-reduced-motion: reduce)` in tokens.css - disables all transitions
- Text contrast: CSS variables use WCAG AA compliant colors
- Skip link: `.skip-link` - Custom CSS accessibility class
- Screen reader: `.sr-only-live` - Custom CSS for screen reader-only content

## Styling Change Reference

### To Change Brand Color
1. Edit `src/styles/tokens.css` - Update `--color-primary: #NEWCOLOR` in `:root`
2. Dark mode automatically adjusts via the `.dark` block
3. All `.btn-primary`, `.text-primary`, `.border-primary` styles automatically update

### To Change Typography Sizing
1. Edit `src/styles/tokens.css` - Modify `.text-h1`, `.text-body`, etc. font-size values
2. All uses of these classes automatically update across the app

### To Change Spacing System
1. Edit `tailwind.config.js` - Modify the `spacing` scale
2. All Tailwind utilities (`p-4`, `gap-2`, `space-y-3`, etc.) regenerate

### To Change Surface Colors
1. Edit `src/styles/tokens.css` - Update `.bg-surface-*` classes
2. Or update CSS variables: `--color-surface-primary`, `--color-surface-secondary`
3. All components using these classes automatically update

### To Add New Component Style
1. Add to `src/index.css` in an appropriate `@layer` block
2. Or add to `src/styles/tokens.css` for semantic color classes
3. Use CSS variables for colors to support theme system and dark mode
4. Test with both light and dark modes

This three-layer system provides:

## Choosing the Right Style (Decision Tree)

Use this quick checklist when building a UI element:

### 1. Text?
- Headline or section: `.text-h1` (32px) / `.text-h2` (24px) / `.text-h3` (20px)
- Body copy: `.text-body` (16px)
- Labels/captions: `.text-caption` (14px)
- Small text: `.text-small` (12px)
- Helper text classes: `.label-text`, `.help-text`, `.heading-text`, `.secondary-label-text`

### 2. Buttons?
- Primary action: `.btn-primary`
- Secondary/outline: `.btn-secondary`
- Neutral/utility: `.btn-neutral`
- Destructive: `.btn-danger`
- Subtle/minimal: `.btn-ghost` (for in-page actions)
- Timer controls: `.btn-timer-start` (large start button)
- Exercise actions: `.btn-exercise` (full-width, touch-friendly)
- **Do not handcraft button colors**; use the button classes and add layout utilities (e.g., `w-full`, `text-sm`)

### 3. Surfaces/cards?
- Generic containers: `.bg-surface-0` (light) / `.bg-surface-800` (dark) with `.shadow-token-sm|md|lg`
- Generic card: `.card` (auto-hover states, shadows)
- Exercise listings: `.exercise-card`, `.exercise-card.selected`, `.exercise-card.favorite`
- Home page cards: `.upcoming-workout-card`, `.insights-card`
- AI coaching: `.ai-insight-card` (left-border accent)
- Empty states: `.empty-state-card` (gradient background)
- Add borders with `.border-surface-*` tokens if needed; prefer tokenized text colors

### 4. Status/feedback (success/warn/error)?
- Use status tokens: example warning card: `bg-warning-soft border border-warning text-warning`
- Avoid raw `red-500`, `yellow-400`, etc.

### 5. Progress bars?
- Use `.progress > .progress__track > .progress__bar`
- Set width via CSS var: `<div class="progress__bar" style={{ ['--progress' as unknown as string]: value }} />`
- On colored backgrounds: Use `.progress--inverse` modifier for white track/bar

### 6. Badges/pills?
- Filter toggles: `.badge-selected`, `.badge-unselected`
- Status badges: `.badge-primary`, `.badge-success`, `.badge-warning`
- Muscle groups: `.muscle-group-badge`

### 7. Timer display specifics?
- Use `.timer-text-shadow-lg|sm` for overlayed white text legibility
- Fixed demo sizes: `.timer-square-280`, `.timer-rect-560x320` (prefer responsive wrappers when possible)
- Position overlays: `.video-inset-10` (10px inset from all edges)
- For video performance: `.gpu-accelerated`

### 8. RTL-sensitive icons/buttons?
- Apply `.nav-more-button` for the More menu; add `.catalog-selector` to scroll controls
- Do not use inline `style={{ direction: 'ltr' }}`

### 9. Accessibility helpers?
- Live region: `.sr-only-live` for offscreen assistive texts
- Respect reduced motion (`motion-reduce:*`) and avoid rapid, decorative animations

## Tailwind Usage Policy

### Use Tailwind for:
- Layout and structure: `flex`, `grid`, `gap`, `p-*`, `m-*`, `w-*`, `h-*`, `rounded-*`, etc.
- Responsive adjustments: `sm:*`, `md:*`, `lg:*`
- State modifiers: `hover:*`, `focus:*`, `disabled:*`, `motion-reduce:*`

### Avoid Tailwind for:
- Colors for text/background/borders in components. Use tokens/utilities in `tokens.css`
- Typography sizing and semantic roles; use `.text-h*`, `.text-body`, `.text-caption`, `.text-small`

## i18n, RTL, and Accessibility

### Internationalization (i18n)
- Never hardcode strings. All user-visible text and ARIA labels go through `t()` or `<Trans>`
- Related guides: `docs/i18n-guide.md`, `docs/i18n/key-styleguide.md`

### Right-to-Left (RTL) Support
- The app automatically toggles `dir` and `body.rtl` for Arabic and other RTL languages
- Use logical utility classes and the RTL protections from tokens (`.nav-more-button`, `.catalog-selector`)
- Do not inline `direction` styles
- Test Arabic (`ar`) mode on mobile widths

### Accessibility (WCAG 2.1 AA)
- Ensure proper color contrast (tokens handle most cases automatically)
- Touch target sizing: minimum 44×44px for interactive elements
- Focus outlines: Maintain visible focus states on buttons/inputs
- Announce important updates with `.sr-only-live` live regions
- Respect `prefers-reduced-motion` - avoid rapid, decorative animations
- Zero horizontal overflow on mobile (min 320px width)

## Adding New Styles & Components

When a new pattern is needed (and it doesn't already exist):

### 1. Check tokens and patterns first
- If an existing tokenized class or pattern fits (e.g., `btn-*`, `text-*`, `progress`, status tokens), use it

### 2. If a new utility is truly needed
- **Design tokens and semantic utilities**: Add to `apps/frontend/src/styles/tokens.css`
- **Page-specific or component-specific styles**: Add to `apps/frontend/src/index.css` under `@layer components` or `@layer utilities`
- Keep naming semantic and short: e.g., `.badge-neutral`, `.list-divider`, not `.bg-gray-50`
- Provide light/dark variants via CSS variables if color-related

### 3. New reusable component
- Place in `apps/frontend/src/components/ui/` (e.g., `ProgressBar.tsx`, `Badge.tsx`, `Modal.tsx`)
- Compose existing token classes; expose sizing/variants via props rather than new colors
- Add minimal stories/examples in docs or inline usage notes

### 4. Don'ts
- Don't introduce ad-hoc color classes into components
- Don't add inline styles (except CSS var `--progress` on `.progress__bar`)
- Don't bypass i18n for strings or ARIA

### 5. Submitting changes
- Run lint, tests, and a manual 320/375/428px sweep
- Validate RTL and reduced motion
- Update `CHANGELOG.md` for user-visible styling changes

## FAQ

**Q: Can I use Tailwind color utilities?**
- Use tokenized utilities from `tokens.css` instead. Only use raw color classes for quick prototypes (must be cleaned before merging)

**Q: Can I create a new button variant?**
- Discuss with the team first. If approved, add a semantic variant in `tokens.css` with design tokens (light/dark, focus states), then document it in this guide

**Q: Are inline styles ever allowed?**
- Only to pass `--progress` to `.progress__bar` (width). For performance hacks (e.g., GPU layers), a tokenized class exists: `.gpu-accelerated`

**Q: How do I ensure RTL compatibility?**
- Use logical properties/classes and the provided RTL protection classes for navigation icons. Test Arabic (`ar`) mode on mobile widths

**Q: What design spec should I follow?**
- Refer to `docs/ui-ux/ui-specs.md` for official UI specification and visual guidelines
