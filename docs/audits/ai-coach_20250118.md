### **Critical Issue: coaching_ai_cache Table Missing**

The `analyze-progress` edge function attempts to read/write from `coaching_ai_cache` table which doesn't exist in production. This causes:
- ❌ Cache misses to fail silently (degrades to always fresh API calls)
- ❌ Increased Mistral API costs (no server-side caching)
- ❌ Slower response times for users

**Required Schema**:
```sql
CREATE TABLE coaching_ai_cache (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  locale text NOT NULL DEFAULT 'en',
  insights_data jsonb NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  expires_at timestamptz NOT NULL,
  UNIQUE(user_id, locale)
);

CREATE INDEX idx_coaching_ai_cache_user_locale ON coaching_ai_cache(user_id, locale);
CREATE INDEX idx_coaching_ai_cache_expires ON coaching_ai_cache(expires_at);
```
